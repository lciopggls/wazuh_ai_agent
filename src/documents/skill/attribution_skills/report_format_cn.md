生成攻击溯源调查报告时，必须严格包含以下章节：

#### **事件概览**
对事件的简要概述（2-3句话），包括攻击类型、受攻击的资产以及造成的影响。

#### **攻击痕迹与来源分析**
列出所有已识别的关键入侵指标（IOC）及攻击来源详情。
- **失陷主机**：（Agent ID/名称）
- **初始攻击入口**：（例如：钓鱼邮件、路过式下载、漏洞利用）
- **恶意文件/载荷**：（列出可疑文件及其完整路径）
- **被利用/篡改的进程**：（列出被攻击者劫持或生成的进程）
- **网络指标**：（列出涉及C2通信或数据外泄的攻击者IP、域名、端口）

#### **进程执行树**
基于你所检索到的日志，手动构建并可视化攻击链。你必须遵循**核心调查原则**：准确追踪具体的恶意执行路径，同时积极过滤掉无关的系统噪声、良性的后台服务以及不相关的兄弟进程。

**关键：格式类型**：
- 进程树必须是**纯文本ASCII树**，使用制表符（`└──`、`├──`、`│`）。不要将其包裹在代码块中。**绝对禁止**：Mermaid（`graph TD`、`flowchart`、`sequenceDiagram`）、JSON、XML、HTML或任何结构化格式。

**进程树可视化规则**：
- 呈现进程树时，每个进程节点必须恰好占用**一行**。每个节点的行必须明确显示以下**三个元素**，且仅显示这三个元素：
  1. **进程名称**
  2. **PID**
  3. **时间戳**（必须严格格式化为**北京时间 / UTC+8**）。
     - **不允许占位符**：你必须提取并写入实际的数字时间值（例如 `2020-09-04 15:30:54.541`）。绝对不要输出描述性文本、括号或占位符。你必须回顾检索到的上下文并填入真实值。
     - **关键时区规则**：计算前仔细检查原始日志。如果时间戳字符串已经包含 `+0800`，则它已经是北京时间——**你必须直接使用，不要额外加8小时**。只有在转换原始UTC字段（例如以 `Z` 结尾的时间或 `utcTime` 字段）时，才需要数学上加8小时。
- **关键过滤规则**：
  - **单一攻击链聚焦（最高优先级）**：进程树必须**仅**包含与攻击属于**同一因果链**的进程。使用 `ParentProcessId` + **时间戳邻近性**作为主要的关联方法——子进程的时间戳必须在其父进程之后不久，且其 `ParentProcessId` 必须与父进程的 `PID` 匹配。如果某个进程源自不同的父进程树（例如，通过 WmiPrvSE.exe 触发的计划任务、通过 svchost.exe 触发的服务进程，或任何与攻击入口点无关的系统机制），则其为**噪声**，必须排除，即使它与攻击处于同一时间窗口。
  - **PID + 时间戳关联**：你必须使用 **PID 配合时间戳**来建立进程谱系：
    - 子进程的 `ParentProcessId` 必须等于父进程的 `PID`。
    - 子进程的时间戳必须在父进程的时间戳**之后**（合理窗口内，通常为秒到分钟级）。
    - **PID 复用注意**：操作系统可能会回收 PID。如果你遇到两个 PID 相同但时间戳相距甚远或执行上下文不兼容的进程，应将它们视为不同的实体。使用时间戳排序来消除歧义。
  - **禁止孤立合并**：如果某个进程的 `ParentProcessId` 与树中已有任何节点的 `PID` 都不匹配，则**不得**将其附加到已有树上。不要仅凭关键词搜索结果或进程名相似性来臆造链接。**日志不完整的例外**：如果日志缺失导致无法在两个明显属于同一攻击的进程组之间建立 `ParentProcessId` 链接（同一用户、同一时间窗口、命令模式一致），则将它们作为独立树呈现，并附简要说明解释推断出的关联，而不是强行链接或丢弃它们。
  - **评估兄弟进程**：如果父进程产生了多个子进程分支，需批判性地评估其相关性。**仅包含**在因果上属于攻击链的兄弟进程。**排除**明显良性、无关的后台噪声（例如，正常的操作系统后台任务、自动更新程序、遥测进程）。将可视化聚焦于所有对恶性叙事有贡献的分支。
  - **隔离特定执行链**：如果发现对同一载荷的多次攻击或多次执行（例如，重复的计划任务），**仅聚焦**于用户明确请求的**特定执行实例**（时间范围或PID）。如果用户未指定目标，则默认选择最近的一次执行。**不要**将不同历史执行中的进程混入同一棵树中。
  - **隐藏未知根节点**：如果树的根节点为 "Unknown" 或缺少 PID/时间戳，**不要**显示它。从链中第一个已识别的有效进程开始可视化。
  - **时间一致性检查**：确保子进程的时间戳**不早于**其父进程。如果发现此类情况（例如，父进程 @ 18:55，子进程 @ 18:16），表明存在逻辑错误或PID复用。你必须**标记此异常**或排除不一致的父节点，以维护有效的时间线。

示例格式：
```
└── PID 404 (explorer.exe) @ 2026-03-05 09:00:00.000
    └── PID 1234 (cmd.exe) @ 2026-03-05 10:00:00.123
        ├── PID 5678 (whoami.exe) @ 2026-03-05 10:00:01.456
        └── PID 5680 (payload.exe) @ 2026-03-05 10:00:01.500
```

错误格式 — 每个进程节点必须恰好占一行。不要将节点拆分为多行：
```
└── PID 7624 (cmd.exe) @ 2026-03-25 17:13:36.360
    └── Command: "C:\Windows\System32\cmd.exe" /c script.bat
        ├── PID 3244 (cmd.exe) @ 2026-03-25 17:13:52.939
        │   └── Command: dir /b /a-d .\test-sets\"discovery"\*.bat
```

#### **攻击时间线与执行流程**
基于进程树的命令行证据，按时序将事件映射到 MITRE ATT&CK 战术阶段。
示例：
- **[2026-03-05 10:00:01.456]** - **[执行 / T1059.001]**：`powershell.exe` 以隐藏窗口样式和 base64 编码命令启动。
- **[2026-03-05 10:00:01.500]** - **[命令与控制 / T1105]**：载荷启动了指向可疑外部IP的 `Invoke-WebRequest`。

#### **总结与建议**
对调查发现、横向移动证据以及可操作的后续步骤的全面总结。
- **使用的工具**：被滥用的合法工具（如 mshta.exe、powershell.exe）与恶意载荷的对比。
- **网络行为**：与内部/外部 IP 的通信、可疑域名以及 C2 基础设施的设立迹象。
- **横向移动/数据外泄**：横向移动、USB 使用或数据外泄的证据（或缺乏证据）。
- **用户活动**：导致事件发生的用户行为分析（如浏览历史、文件执行）。
- **关键结论与建议**：用于修复和加固的可操作后续步骤。
