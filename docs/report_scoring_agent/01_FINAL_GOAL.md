# 报告评分智能体：最终目标与固定约束

> 更新日期：2026-08-20  
> 文档性质：长期产品目标和验收边界

## 1. 最终目标

建设一个可独立运行、可从项目完整前后端调用的报告评分智能体，对不同攻击溯源智能体生成的报告进行统一、可追溯、可比较的质量评估。

最终系统应形成以下闭环：

1. 登记测试用例、被评分智能体和报告。
2. 基于固定版本的评分标准构造评分上下文。
3. 通过 LangGraph 评分图调用模型。
4. 校验并持久化评分 attempt、结构化结果和可读结果。
5. 在前端查看单次详情、历史记录和多智能体横向对比。

## 2. 固定业务约束

- 测试用例、报告、评分标准、评分 attempt 和评分结果必须具有稳定标识。
- 每次评分必须记录标准版本、被评分智能体、报告来源、请求标识、状态和时间。
- 同一请求应具备幂等性；重评分必须显式发起，不得因页面刷新产生重复任务。
- 最新有效评分只从成功且符合当前标准版本的结果中选取。
- 未评分、评分失败和模型不可用必须以明确状态或错误码表达，不能伪装为 0 分。
- 前端展示以服务端结构化结果为准，不从模型自然语言回答中二次猜测分数。
- 报告评分功能必须可通过环境开关关闭，关闭时不影响现有 AI 聊天等主流程。

## 3. 评分输出约束

- 总分范围为 0～100，并由服务端根据六个维度及扣分规则重算。
- 每个维度必须包含分数和说明。
- 结果必须包含优点、缺点和必要的根因归纳。
- 结构错误、字段缺失、分数越界或规则冲突必须在持久化成功结果前被拒绝。
- 模型原始表达可用于审计，但 API 和前端消费的是验证后的统一数据结构。

## 4. 当前完成度

- LangGraph 评分图、后端接口、文件持久化、前端入口、详情/历史/对比和功能开关已经实现。
- Studio 与完整前后端两条人工流程已通过。
- 正式代码已提交并推送，当前等待独立代码审查。

## 5. 不属于当前小阶段的目标

- 不要求本阶段完成自动分数与人工分数的精确对齐。
- 不要求继续跑完所有测试用例、所有被评分智能体和所有重复轮次。
- 不把报告评分智能体接入 Wazuh 攻击执行或实时告警采集链路。
- 不在没有用户授权时提交本地测试文件、仿真产物或运行数据。

独立审查闭环后，项目计划人员可再决定是否进入评分校准、批量评估、更多模型支持或生产化存储阶段。
