# 报告评分智能体：本地预置答案案例双入口需求

> 更新日期：2026-08-28
> 文档性质：当前产品需求、计划与实施的唯一需求事实源

## 1. 核心需求

测试只使用已经在本机保存完整评分答案的案例。系统在测试过程中不创建案例、不生成标准答案，
也不要求普通测试员准备锚点、Archives、Ground Truth、遥测边界或预期报告。

一份可评分输入由以下关系构成：

```text
一份溯源报告 + 测试员选择的本地已有案例 + 实际生成报告的被测智能体
```

系统直接读取所选案例已经保存的评分材料并调用现有评分智能体。

## 2. 案例准备边界

案例准备发生在测试之前，由开发人员或具备安全知识的案例设计人员离线完成。一个可用案例应
包含现有注册表要求的 manifest、评分输入、Ground Truth、遥测边界、预期报告、证据材料和
评分标准版本，并通过路径、哈希和内容完整性校验。

这里的“离线”表示在普通测试页面之外准备，不表示必须断网或换回开发主机。新主机可以由案例
设计人员配合独立的辅助 AI 工具，根据攻击脚本、真实执行结果和 Wazuh 证据保存上述文件；该
过程不增加产品代码，也不得把答案提供给被测智能体。详细操作见
[`12_NEW_HOST_NEW_ATTACK_TEST_FLOW.md`](./12_NEW_HOST_NEW_ATTACK_TEST_FLOW.md)。

普通测试页面只消费已启用且完整的本地案例，不能创建、编辑、确认或发布案例。

SIM-204～SIM-206 已满足上述前置条件，可直接重复测试。新攻击案例必须先按
`12_NEW_HOST_NEW_ATTACK_TEST_FLOW.md` 生成并安装正式案例文件；安装完成后，它与固定基准使用同一
套登记和评分代码，不引入第三个产品入口。

## 3. 入口一：AI 对话报告

1. 测试员选择本地已经准备好答案的事件。
2. 在 AI 对话中向溯源智能体发送“对以下日志进行攻击溯源：<JSON 日志>”。
3. 智能体生成最终溯源报告。
4. 测试员可以：
   - 只把报告保存为本地 Markdown；或
   - 选择对应的本地案例和实际被测智能体，保存并登记到评分系统。
5. 登记后使用现有评分、详情、历史和对比能力。

对话中的 JSON 用于溯源智能体调查。本阶段不要求评分登记接口再次提取该 JSON、计算锚点哈希
或据此创建案例。报告与案例的对应关系由测试流程和操作员选择保证。

## 4. 入口二：本机报告上传

最少必需输入：

- 智能体生成的报告文件；
- 对应的本地已有案例；
- 实际生成报告的被测智能体。

可选输入为 Thread ID、Run ID 和备注。

本入口不要求：

- `anchor.json`；
- 攻击 RUN ID；
- 运行包或评分包；
- Ground Truth、遥测边界、预期报告或 Archives 文件；
- 人工关系确认和确认人。

登记成功后与 AI 对话入口共用同一评分链路。

## 5. 服务端规则

- 只允许登记到注册表中已启用且完整的本地案例。
- 只允许使用智能体目录中存在的被测智能体标识。
- 报告必须非空、格式受支持、不能超过 1 MiB，且位于安全路径边界内。
- 本地保存不得覆盖同名但内容不同的既有报告；同名同内容请求可以安全复用已有文件。
- 重复报告按现有 SHA、案例和智能体幂等规则处理，不能静默制造重复样本。
- 登记失败必须返回明确错误；AI 对话入口的评分登记失败不得阻断报告本地保存。
- 未评分和评分失败不能显示为 0 分。
- 重评分必须显式发起，并保留旧 attempt 和结果。
- 不创建案例草稿、Archives 快照、发布审计或新案例目录。

## 6. 前端规则

- AI 最终报告同时提供“保存报告”和“保存并登记评分”。
- 登记弹窗只显示案例、被测智能体和可选审计字段。
- 本机上传表单只显示报告文件、案例、被测智能体和可选审计字段。
- 页面不显示新建案例、锚点上传、RUN 时间窗、Archives 查询、答案编辑、确认、发布或恢复。
- 成功和失败必须有可持续查看的明确提示。保存成功显示实际本地路径，登记成功同时显示
  `report_id`；登记失败仍显示已经保存的本地路径。
- 同一消息成功保存或登记后禁用对应按钮；重复操作不得因页面刷新自动触发评分。
- 测试模块和评分模块功能开关继续有效。

## 7. 明确删除的旧功能

- AI Human Input 锚点提取和匹配；
- 本机 `anchor.json` 上传与预检；
- 案例草稿及状态机；
- Archives 查询和证据冻结；
- 页面编辑 Ground Truth、遥测边界和预期报告；
- staging、动态发布和故障恢复；
- Studio inbox 报告导入入口和目录；
- 攻击 RUN、确认人、锚点 SHA 等来源补录合同；
- 运行包、评分包和动态案例实例化方案。

## 8. 验收标准

### AI 对话入口

- 最终报告能只保存到本机。
- 最终报告能选择本地案例和被测智能体后登记。
- 登记失败时本地报告仍保存成功。
- 不要求锚点或答案材料，不产生草稿或新案例。

### 本机报告入口

- 上传报告并选择本地案例和被测智能体后可以登记。
- 未选案例、未选智能体、空报告、未知案例或未知智能体时明确拒绝。
- 不要求上传 `anchor.json` 或任何答案文件。
- 登记后可首次评分、重评分，并查看详情、历史和对比。

### 公共回归

- 本地全部已启用完整案例可以读取。
- 评分图、六维合同、总分重算、失败状态和幂等逻辑保持不变。
- 关闭功能开关时不影响正式 AI 助手。
- 普通测试界面不暴露动态案例准备能力。
- 测试期间不写入新案例目录、草稿、Archives 快照或发布审计。

## 9. 数据保留

清理旧功能时不得连带删除现有仿真资料、评分运行历史、SIM-207 本地案例、知识图谱输入报告、
stash 或其他无关用户文件。是否清理这些数据必须另行取得用户的明确授权。

案例设计目录、Wazuh 原始导出和运行记录属于测试资料，不因产品代码提交而自动纳入版本控制。
若需要跨主机共享正式案例，必须由案例负责人单独确认共享范围、隐私和证据脱敏边界。
