## 1. 当前业务边界

报告评分只评价已经生成的攻击溯源报告。所有用于评分的案例及标准答案必须在测试开始前由
开发人员或案例设计人员保存在本机，并通过现有案例注册表完整性校验。

测试阶段只有两个报告入口：

1. **AI 对话入口**：测试员向溯源智能体发送“对以下日志进行攻击溯源：<JSON 日志>”。
   该事件对应的评分案例和标准答案已经保存在本地。报告生成后，测试员选择对应案例和实际
   被测智能体，可直接保存并登记评分，也可只保存为本地 Markdown。
2. **本机报告入口**：测试员上传溯源智能体已经生成的报告，选择对应的本地案例和被测智能体，
   然后直接登记评分。

系统不在测试过程中创建案例、生成答案或冻结证据。本机报告入口不再要求上传
`anchor.json`。Thread ID、Run ID 和备注只作为可选审计信息。

## 2. 已保留能力

- LangGraph `report_scoring_agent`、DeepSeek 模型调用和六维结构化评分。
- 服务端字段校验、总分重算、负向行为规则以及失败状态记录。
- 本地案例注册表及评分上下文加载。
- 报告、评分 attempt 和结果的文件持久化、幂等登记和显式重评分。
- 报告列表、评分详情、历史记录和多智能体对比。
- AI 对话报告保存与可选评分登记。
- 本机报告文件上传与评分登记。
- `VITE_ENABLE_TEST_MODULE` 和 `VITE_ENABLE_REPORT_SCORING` 两层功能开关。

两个入口的操作反馈已补齐：AI 报告保存成功会持续显示实际本地路径，保存并登记成功还会显示
`report_id`；如果登记失败，会明确保留“本地报告已保存”的路径和登记错误。成功按钮保持禁用，
避免对同一消息重复点击。本机上传成功会显示 `report_id` 和存储位置，并真正清空浏览器文件选择。

本地 Markdown 保存同时拒绝空内容和超过 1 MiB 的内容。同名同内容请求复用已有文件；同名不同
内容分配带序号的新文件，不会覆盖原报告。

当前评分标准为 `v3.0`。六个维度为：初始事件识别准确性、关键证据检索与覆盖度、
事件时间线准确性、攻击链重建与因果分析、MITRE ATT&CK 映射质量和未发生行为核验。

## 4. 本地案例规则

- 评分页面只列出本地案例目录中已启用且通过完整性校验的案例。
- 案例必须在测试前保存好 Ground Truth、遥测边界、预期报告、冻结证据、评分输入和标准版本。
- 测试员负责选择与报告对应的案例；当前系统不声明能够从报告正文证明其真实来源。
- 新增或修改标准答案是离线案例维护工作，不通过普通测试页面完成。
- 新主机准备新攻击案例时，按照
  [`12_NEW_HOST_NEW_ATTACK_TEST_FLOW.md`](./12_NEW_HOST_NEW_ATTACK_TEST_FLOW.md) 分阶段保存脚本设计答案、
  实际运行证据和最终评分答案；允许独立辅助 AI 工具保存文件，但不增加产品代码逻辑。
- 已有报告和评分历史不得因案例维护被静默覆盖。

Git 跟踪的固定案例包括 SIM-204～SIM-206。它们可直接用于重复验证当前双入口评分流程。新攻击
案例必须先按新主机流程完成答案制作和案例安装，再进入与 SIM-204～SIM-206 相同的报告登记与
评分链路。

本机现有 SIM-207 数据按本轮删除边界保留，但它是未跟踪的历史本地数据，不属于本轮拟提交的
固定基准。是否在某台测试主机上临时使用，取决于其 manifest 是否启用并能通过注册表校验。
